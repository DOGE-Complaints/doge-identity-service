# Как подготовить песочницу (sandbox) Authentigate — простая инструкция

> **Для кого:** для тебя, чтобы ты могла сама получить тестовый доступ к Authentigate, пока Claude пишет код.
> **Что такое Authentigate:** это сервис SK ID Solutions, через который человек подтверждает, что он реальный, с помощью эстонских Smart-ID / Mobile-ID / ID-карты. Наш сервис будет «спрашивать» Authentigate: «это точно настоящий человек?».
> **Что такое sandbox/песочница (demo):** бесплатная **тренировочная** версия Authentigate. Там нет реальных людей — только тестовые аккаунты. На ней безопасно отлаживать интеграцию, ничего не платя.
> **Результат этой инструкции:** у тебя на руках 3 секретных значения (Client ID, Client Secret, Redirect URI) + подтверждённый тестовый аккаунт. Их потом вставим в настройки сервиса — и можно тестировать живой вход.
> Это «как сделать руками» — companion к задаче [SPIKE-IDS-EID-09](../tasks/backlog-stories/SPIKE-IDS-EID-09-authentigate-demo-access.md).

---

## Словарик (чтобы не пугали слова)

- **Client ID / Client Secret** — это как «логин и пароль» нашего сервиса в Authentigate. Их выдаёт Authentigate при регистрации. Secret — секретный, его нельзя никуда выкладывать.
- **Redirect URI** — адрес-«куда вернуть пользователя» после того, как он залогинился через Smart-ID. У нас это всегда `.../auth/authentigate/callback`. Этот адрес надо заранее зарегистрировать в Authentigate, иначе он откажется работать («куда я тебя верну, я этот адрес не знаю»).
- **Allowed IPs** — список IP-адресов (это «номер дома» сервера в интернете), с которых Authentigate разрешает обращаться. Нужно, чтобы посторонние не пользовались нашими ключами.
- **Q-аккаунт (Qualified)** — тестовый Smart-ID повышенного уровня. Только такие работают в Authentigate; обычные тестовые (Basic/NQ) **не** работают — это частая ловушка.

## Шаг 0 (по желанию, 5 минут) — просто посмотреть, как это выглядит

Без всякой регистрации можно открыть demo-страницу Authentigate в браузере и потыкать вход — увидеть, как выглядит экран Smart-ID/Mobile-ID. Это помогает понять, что мы вообще делаем.
👉 Официальная страница тестирования: <https://sk-eid.github.io/authentigate-documentation/demo.html>

Ничего записывать не надо — это просто «осмотреться».

## Шаг 1 — Запросить demo-доступ (Demo Plan, бесплатно)

1. Открой портал SK (e-Service Portal) — ссылка и точные кнопки указаны на той же официальной странице: <https://sk-eid.github.io/authentigate-documentation/demo.html>
2. Запроси **Demo access** и выбери **Demo Plan** (он бесплатный).
3. В форме-заявке укажи, что это **тестовое (development) окружение**.
4. Отправь и дождись подтверждения от SK (придёт ответ/письмо).

> 💡 Если форма попросит описать use-case (для чего), напиши простыми словами:
> «One-time human verification for civic story submission. Not financial KYC, not AML, not signing.»
> (Это: «разовая проверка, что пользователь — настоящий человек, для подачи гражданских обращений. Не банковская проверка, не подпись документов».)

---

## Шаг 2 — Зарегистрировать наш demo-клиент

После подтверждения нужно зарегистрировать «клиента» (наш сервис). Officz-инструкция: <https://sk-eid.github.io/authentigate-documentation/api/registration.html>

В заявке/форме укажи такие значения:

| Поле | Что вписать | Пояснение |
|------|-------------|-----------|
| **Service Name** | `DOGEstonia` | название нашего сервиса |
| **Redirect URI** | `https://<АДРЕС-СЕРВЕРА>/auth/authentigate/callback` | см. Шаг 3 про адрес |
| **Allowed Countries** | `EE` | пока только Эстония |
| **Authentication methods** | Smart-ID, Mobile-ID, ID-card | три эстонских метода |
| **Allowed IPs** | IP сервера (см. Шаг 3) | откуда нам разрешено обращаться |

В ответ Authentigate выдаст (это и есть главный «улов»):
- **Client ID**
- **Client Secret**

✍️ **Запиши их в надёжное место** (не в публичный чат). Secret больше нигде не показывается.

---

## Шаг 3 — Определиться с адресом (Redirect URI) и IP

Authentigate должен «знать», на какой адрес возвращать пользователя, и этот адрес должен быть **доступен из интернета**. Возможны два варианта — выбери, как тебе удобнее:

- **Вариант А (проще, если сервис уже где-то развёрнут):** взять публичный адрес нашего развёрнутого сервиса. Тогда Redirect URI = `https://<наш-публичный-домен>/auth/authentigate/callback`, а Allowed IPs = IP этого сервера.
- **Вариант Б (локально на твоём компьютере):** поднять «туннель» — это утилита, которая делает временный публичный адрес для локального сервиса (например, ngrok/cloudflared). Тогда Redirect URI = `https://<случайный-адрес-туннеля>/auth/authentigate/callback`.

> ⚠️ **Самое важное правило:** Redirect URI, который ты зарегистрировала в Authentigate, должен **буква-в-букву** совпадать с тем, что мы потом пропишем в настройках сервиса. Любое отличие (http/https, лишний слэш) — и вход не сработает.

Если сейчас непонятно, какой адрес — это нормально. Можно зарегистрировать любой реальный публичный адрес, а если он поменяется — обновить Redirect URI в портале позже.

---

## Шаг 4 — Получить тестовый аккаунт для входа

Чтобы потом проверить живой вход, нужен **Smart-ID Qualified (Q)** тестовый аккаунт.
👉 Тестовые аккаунты — там же: <https://sk-eid.github.io/authentigate-documentation/demo.html>

> ⚠️ Обычные Smart-ID **Basic / NQ** тестовые аккаунты с Authentigate **не работают** — нужны именно **Q (Qualified)**. Это частая причина «почему не пускает».

## Что записать и передать (итог)

После всех шагов у тебя должно быть готово 4 значения + 1 аккаунт. Их я попрошу, когда дойдём до подключения:

```
AUTHENTIGATE_ISSUER        = https://oidc.demo.sk.ee     ← уже известно (demo SK), вписывать не надо
AUTHENTIGATE_CLIENT_ID     = <из Шага 2>
AUTHENTIGATE_CLIENT_SECRET = <из Шага 2>   (секрет!)
AUTHENTIGATE_REDIRECT_URI  = <из Шага 3, ровно как зарегистрировала>
+ тестовый Smart-ID Q аккаунт для проверки входа
```

> Остальное (scopes, методы входа `sid_ee/mid_ee/idcard_ee`, язык интерфейса) код уже знает и подставит сам — тебе про это думать не нужно.

Куда положить значения: либо передать мне, либо вписать в файл `.env` сервиса в поля `AUTHENTIGATE_CLIENT_ID` / `AUTHENTIGATE_CLIENT_SECRET` / `AUTHENTIGATE_REDIRECT_URI` (рядом уже есть пустые заготовки в [`.env.example`](../../.env.example)). `.env` не коммитится в git — секреты не утекут.

## Если что-то идёт не так (быстрая помощь)

- **«Вход не возвращает обратно / ошибка redirect»** → Redirect URI в портале не совпадает с настройкой буква-в-букву. Сверь оба.
- **«Smart-ID не пускает в demo»** → используешь Basic/NQ аккаунт вместо **Q**.
- **«Отказ по IP»** → не добавлен (или сменился) Allowed IP сервера/туннеля.
- **Любые специфичные детали Authentigate** → официальная документация: обзор <https://sk-eid.github.io/authentigate-documentation/api/overview.html>, окружения <https://sk-eid.github.io/authentigate-documentation/environments.html>.
