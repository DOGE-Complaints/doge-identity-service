# Runtime-документация doge-identity-service

## Зачем этот раздел

Это «карта местности» сервиса **по факту кода** — что он умеет **прямо сейчас**, а не что задумано. Если ты впервые открываешь проект и хочешь понять «что это, как устроено и где что лежит» — начни отсюда. Планы и требования (часто опережающие код) живут отдельно в [`../requirements/`](../requirements/); не путай их с этим разделом.

## Что такое doge-identity-service одним абзацем

Это сервис **идентичности и авторизации** платформы DOGEstonia. Простыми словами он отвечает на три вопроса: «кто ты?» (вход через Supabase Auth), «ты реальный проверенный человек?» (eID-верификация через эстонский ID) и «какому приложению можно действовать от твоего имени?» (OAuth-сервер для ChatGPT). Сам сервис **не занимается историями и жалобами** — это работа соседнего сервиса `doge-complaints-gateway`. identity только подтверждает личность и выдаёт/проверяет токены.

## Легенда статусов

В документах у каждого блока стоит метка зрелости:

- ✅ **работает** — есть рабочий код, покрыт тестами.
- 🟡 **заглушка** — маршрут/слой есть, но пока отвечает «501 не реализовано» или это mock.
- ⚪ **заготовка** — есть схема/поля/контракт, но поведения ещё нет.
- ❌ **заявлено, но в коде нет** — упомянуто в требованиях/конфиге, реализации нет.
